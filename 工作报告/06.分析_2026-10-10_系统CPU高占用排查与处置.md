# 系统 CPU 高占用排查与处置

> 编号：06 | 日期：2026-10-10 | 类别：分析 | 项目：系统维护

---

## 一、背景

用户反馈系统 CPU 占用偏高，系统整体 CPU 负载持续处于 55%~60% 区间。为保障开发环境流畅运行，对 Windows 宿主机与后台虚拟化子系统的 CPU 资源消耗来源进行了系统性排查与处置。

## 二、核心内容

### 1. 现象分析与根因定位
通过处理器时间计数器采样（User/Privileged Time）与进程级别性能分析，定位到系统整体高负载的主要原因：

1. **特权/内核时间异常（Privileged Time 达 31.7%）**：
   - **Tokens HUD 双实例并发**：后台存在两个并发运行的 `node.exe` 实例（PID 16632、22688），执行 `C:\Users\zy\.antigravity-tokens-hud\index.js`。
   - **高频子进程创建**：`index.js` 设置了 `1000ms`（1 秒）轮询间隔，每次循环均调用 `child_process.execFile` 重新拉起完整的 `python.exe` 解析 token 统计数据。双实例并发导致每秒产生 2 次全新的 Python 进程创建与销毁。
   - **连锁防病毒扫描与 UI 重绘**：Windows 下高频创建进程引发句柄与虚拟内存密集操作，同时触发 Windows Defender（`MsMpEng.exe`）常态拦截扫描（消耗 3%~5% CPU）；且通过 CDP 调试协议每秒向 Antigravity 注入脚本重绘，引起前端渲染进程及 GPU 进程持续占用约 10% CPU。

2. **WSL2 9P 共享文件服务忙等待（`vmmemwsl` 占 10%~15%）**：
   - 检查 WSL2 内部发现，PID 6 的 `plan9`（9P 跨系统文件服务器）CPU 占用高达 32.5%（累计运行超 6 分钟）。
   - 深入检查文件描述符发现其打开了 `/home/zywsl/opencode-projects/agy-token-hud`，处于跨系统文件监视的 busy-wait 忙循环状态。

### 2. 处置方案与执行
1. **清理失控进程**：强制终止重复的 `node.exe` 实例及所有挂起的 `python.exe` 进程。
2. **重置 WSL2 状态**：执行 `wsl --shutdown`，释放处于忙循环锁定的 `plan9` 句柄与内存映射。
3. **优化代码轮询策略**：将 `C:\Users\zy\.antigravity-tokens-hud\index.js` 中的轮询周期由 `1000ms` 调整为 `5000ms`（降低 80% 调度频次），杜绝下次启动时的资源雪崩。

### 3. 处置效果复测
- **总体 CPU 负载**：由 **54%~60%** 直降至 **11%**（恢复正常基线）。
- **内核特权时间**：回落至正常静默水平（< 2%）。
- **Python / WSL 异常占用**：完全归零。

## 三、结论/建议

1. **避免在轮询逻辑中频繁创建解释器进程**：在 Windows 平台上，频繁创建 `python.exe` 进程开销极重且易受 Defender 实时防护干扰；如需高频监控，建议改用常驻后台进程通信或事件驱动通知。
2. **警惕跨系统文件监控（9P/WSL）**：尽量避免 Windows 工具持续对 WSL 内部目录建立热更新监视，防止 `plan9` 进入忙轮询。
